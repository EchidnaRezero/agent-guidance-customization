# When PowerShell Command Fails

## 목표

Codex 세션에서 발생한 Windows PowerShell 명령 실패를 분석하고 기록합니다.

## 위임

- 커스텀 에이전트를 사용할 수 있으면 실패 분석에는 `powershell_failure_analyst` 커스텀 에이전트를 사용합니다.
- 이 스킬이 발동된 것 자체를 사용자가 `powershell_failure_analyst` 사용을 직접 지시한 것으로 취급합니다. 현재 요청에서 사용자가 해당 에이전트 이름을 명시하지 않아도 같습니다.

## 범위

- Codex 안에서 실행한 Windows PowerShell 명령 실패
- 실행 전에 차단된 명령
- 잘못된 경로나 잘못된 현재 디렉터리
- 따옴표나 escaping 실수
- 신중하게 보고해야 하는 파괴적 명령

## 워크플로

1. 사용자의 목표와 실제로 실패한 PowerShell 명령을 분리합니다.
2. 호출된 프로그램의 문서화되었거나 확립된 결과 규약에 따라 명령이 실제로 실패했는지 확인합니다. 정상적인 부정 결과로 알려진 사례는 `references/misconception-log.md`에서 확인합니다. 예를 들어 `rg` 종료 코드 1은 일치 항목이 없다는 뜻이며 실패가 아니므로, 실패로 분석하거나 기록하지 않습니다.
3. 확인된 실패의 유형을 빠르게 분류합니다.
   - 실행 전에 차단됨
   - 경로 또는 작업 디렉터리 불일치
   - 따옴표 또는 escaping 문제
   - 권한 또는 잠금 문제
   - 현재 런타임에서 허용되지 않는 파괴적 명령
4. 실제 파일 변경이 성공했는지, 일부만 성공했는지, 아예 실행되지 않았는지 명시합니다.
5. 명령이 실행 전에 차단되었다면, 이것이 도구/런타임 정책 문제이지 자동으로 저장소 규칙이나 코드 오류를 뜻하는 것은 아니라고 설명합니다.
6. 비파괴적 우회 방법을 우선합니다. 예: 남은 폴더를 그대로 두기, 수동 정리 제안, 허용된 명령으로만 재시도.
7. 현재 세션에서 직접 재현된 실패에 한해 `references/case-template.md`를 사용하여 `references/failure-log.md`에 짧은 항목을 추가합니다. 먼저 기존 기록을 확인하고 중복 항목은 추가하지 않습니다.
8. 설명은 짧고 구체적으로 유지합니다: 사용자 목표, 실패한 명령, 실패 유형, 완료된 작업, 남은 작업.

## 응답 형태

- 사용자 목표
- 실패한 명령
- 실패 유형
- 실제로 완료된 것
- 안전한 다음 단계

## 참고 자료

- 의심되는 실패를 분류하거나 기록하기 전에 `references/misconception-log.md`를 읽습니다.
- 알려진 실패 패턴과 표현 방식은 `references/failure-log.md`를 읽습니다.
- 새 사례를 추가할 때는 `references/case-template.md`를 사용합니다.
- `references/` 아래의 모든 파일은 영문 단일 원본으로 유지하며 `_KR` 동반 파일을 만들지 않습니다.
