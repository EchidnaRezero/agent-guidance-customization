# When Writing Codebase Analysis Docs

## 작성 기준

### 범위

- 먼저 `when-writes-and-check-md_doc`를 적용합니다.
- 코드베이스 구조, 관계, 동작을 설명하는 문서에만 이 스킬을 적용합니다.

### 구조

- 먼저 하나 이상의 전체상을 보여주고, 그다음 그 전체상에 연결된 세부 섹션으로 내려갑니다.
- 폴더 트리와 파일 트리에는 다이어그램 대신 ASCII를 사용합니다.
- 다이어그램은 주로 구조나 순서, 동작의 전체상을 나타낼 때 사용합니다. 다만 특별히 복잡한 문서이거나 사용자 요청이 있지 않는 한, 다이어그램 수는 문서당 3개 이하로 제한합니다.
- 단순 대응표나 의존성 목록은 표를 사용합니다.

### 다이어그램 의미

- 하나의 다이어그램은 하나의 관계만을 나타내는 화살표를 사용합니다. 다른 관계를 나타내는 화살표가 필요하다면 다이어그램을 분리합니다.
- 각 화살표 의미를 근처 본문, 범례, 캡션 중 한 곳에 적습니다.

### 번호와 연결

- 서로 다른 전체상이 여러 개 있으면 `A`, `B`, `C` 같은 대문자를 각 전체상에 사용합니다.
- 하나의 전체상 안에서는 `A1`, `A2`, `B1`, `B2` 같은 번호가 붙은 세부 섹션을 사용합니다.
- 서로 다른 전체상 사이에서 세부 번호를 섞지 않습니다.
- 전체 구조 다이어그램에서는 각 세부 섹션 계열과 맞는 안정적인 노드 라벨을 사용합니다.
- 뒤의 세부 섹션들에서도 같은 라벨과 번호를 다시 사용해서, 각 세부 내용을 상위 전체상에 다시 연결할 수 있게 합니다.
- 전체 예시는 `references/numbering-and-mapping-example.md`를 봅니다.

### 스타일

- 번호가 붙은 세부 섹션 제목은 `## [A1] name: what it does` 형식을 우선합니다.
- 소제목 설명은 짧고 구체적으로 유지하고, 화면에서 보이거나 직접 확인할 수 있는 동작 중심으로 씁니다.

## 검토 기준

- 해당 문서가 코드베이스 분석 문서인지 애매하면, 이 스킬을 적용하기 전에 사용자에게 확인합니다.
- 문서가 위 작성 기준에 맞게 쓰였는지 확인합니다.
