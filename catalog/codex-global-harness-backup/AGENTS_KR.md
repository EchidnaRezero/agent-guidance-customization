## Policy Scope
- 영어 정본 `AGENTS.md`를 `.codex` 환경의 최상위 전역 정책으로 취급합니다.
- 저장소 로컬 `AGENTS.md` 파일은 해당 저장소의 규칙을 추가하거나 덮어쓸 수 있습니다.

## Language
- 사용자와는 항상 한국어로 대화합니다.
- 사용자가 다른 언어를 요청하지 않는 한 AI용 문서(`AGENTS.md`, `SKILL.md`, 하네스 문서)는 기본적으로 영어로 작성합니다. 사용자용 문서는 기본적으로 한국어로 작성합니다.
- 하네스 문서를 생성하거나 업데이트할 때는 `korean_companion_sync` 커스텀 에이전트를 사용해 영어 정본 문서와 `_KR` 동반 파일을 동기화합니다.
- 사용자와 대화할 때는 전문 용어를 사용하기에 앞서 사용자가 직접 관찰하거나 확인할 수 있는 표현으로 행동과 결과를 설명합니다.

## Writing Docs
- “A가 아니라 B”와 같은 대조적 부정은 A를 거부해야 할 필요가 있을 때만 사용합니다. A가 흔히 생길 수 있는 오해이거나, 안전 문제이거나, 핵심적인 대조인 경우가 이에 해당합니다. 그 외에는 의도한 내용을 직접 서술합니다.
- 미리 정의된 템플릿을 따라 내용을 체계적이고 일관되게 구성합니다.
- 내용이 아니라 문서 자체를 설명하는 메타 표현을 피합니다.
- 문서에서 사용자의 채팅 지시를 언급하거나, 다시 서술하거나, 설명하지 않습니다. 이는 문서 내용이 아니라 에이전트의 행동 규칙입니다.

## Answer Style
- 결론이나 요약을 먼저 제시합니다.
- 한 문단에서는 한 가지 주제만 다루며 분량은 한 문단 정도로 유지합니다. 답변이 길어질 수밖에 없다면 초점을 유지하고, 다음 내용을 짧게 예고하는 한 줄로 마무리합니다.

## Environment
- 기본 실행 환경은 WSL이나 Linux가 아니라 Windows라고 가정합니다.
- 사용자가 직접 실행할 명령을 제안할 때는 PowerShell 전용 동작이 필요하지 않은 한 `cmd` 문법을 우선합니다.
- 현재 환경이 Windows가 아니라면 기본 Windows 환경 지침 적용을 멈추고, 계속하기 전에 해당 환경에 맞는 지침을 확인합니다.

## Workflow
- 적용 가능한 가장 구체적인 저장소 또는 하네스 워크플로를 따릅니다.

## Security
- 프로젝트 보안 수준은 계획 단계에서, 보통 `writing-plans`에서 결정합니다.
- Low: 개인 로컬용. 입력 처리, 경로 처리, 시크릿, 로그, 오류, 권한, 삭제 또는 덮어쓰기 동작을 점검합니다.
- Medium: 외부 API, 민감한 저장 데이터, 공유 기기 접근. Low 수준 항목에 더해 저장과 접근 제어를 검토합니다.
- High: 다중 사용자, 공개 서버 노출, 매우 민감한 데이터. 인증, 인가, 전송 보호, 저장 보호를 각각 분리해 설계합니다.
- 보안 설계가 선택한 수준보다 무거워 보이면 이유를 설명하고 계속하기 전에 확인을 받습니다.

## Git
- 현재 요청에 파일 이력이나 기존 변경 사항이 필요한 증거인 경우에만 읽기 전용 Git 명령을 직접 사용합니다.
- 관련 없는 작업에는 Git 점검을 기본 사전 절차로 수행하지 않습니다.
- 스테이징, 커밋, 푸시, 풀, 병합, 브랜치 또는 워크트리 변경, 변경 취소 또는 정리, 사용자 신원 선택, SSH 계정 점검을 포함한 Git 워크플로 결정과 상태 변경 작업에는 `git_steward` 커스텀 에이전트를 사용합니다.

## Plan And Brainstorming
- 사용자가 원하는 최종 결과를 파악하고, 사용자가 결과를 예측하고 확인할 수 있는 마일스톤을 정의합니다.
- 간단한 시각화 도구가 사용자의 결과 이해에 실질적으로 도움이 될 때 사용합니다. UI 작업에서는 사용자가 행동과 결과를 미리 확인할 수 있도록 HTML 샘플 페이지를 고려합니다.

## Code Guide
- 각 파일, 클래스, 함수에 하나의 명확한 역할을 부여합니다.
- 코드가 무엇을 하는지 나타내는 구체적인 이름을 사용합니다.
- 관련 로직은 함께 둡니다.
- 관련 없는 로직은 분리합니다.
- 변경 요청이 없는 한 기존 프로젝트 패턴을 따릅니다.
- 더 명확하고 유지보수하기 쉬운 방법이 있으면 하드코딩을 피합니다.
- 어떤 이유로든 하드코딩을 사용했다면 사용자에게 알리고 이를 제거하는 재작성을 제안합니다.
- 라이브러리를 사용하기 전에는 가능하면 Context7로 최신 버전을 확인합니다. 호환성과 안정성에 필요하면 버전을 조정합니다.
- Python `venv` 같은 프로젝트 로컬 환경을 우선하고, `pip` 대신 `uv`를 사용합니다.
- 같은 요청의 코드 작업이 이미 네 번 이상 실패했다면, 추가로 코드를 변경하기 전에 원인을 디버깅합니다.
