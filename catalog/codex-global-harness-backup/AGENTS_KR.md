## Policy Scope
- 이 파일은 `.codex` 전역 환경의 최상위 정책을 설명하는 한국어 동반 문서입니다.
- 저장소 로컬 `AGENTS.md`는 해당 저장소에서만 적용되는 규칙을 추가하거나 덮어쓸 수 있습니다.

## Language
- 사용자와는 항상 한국어로 대화합니다.
- 사용자가 다른 언어를 요청하지 않는 한 하네스 문서는 기본적으로 영어로 작성합니다.
- 하네스 문서를 생성하거나 업데이트할 때는 `korean_companion_sync` 커스텀 에이전트를 사용해 영어 정본 문서와 `_KR` 동반 파일을 동기화합니다.

## Environment
- 기본 실행 환경은 WSL이나 Linux가 아니라 Windows라고 가정합니다.
- 사용자가 직접 실행할 명령을 제안할 때는 PowerShell 전용 동작이 필요하지 않은 한 `cmd` 문법을 우선합니다.
- 현재 환경이 Windows가 아니라면 기본 Windows 규칙 적용을 멈추고, 계속하기 전에 해당 환경에 맞는 지침을 확인합니다.

## Workflow
- 적용 가능한 가장 구체적인 저장소 또는 하네스 workflow를 따릅니다.

## Security
- 프로젝트 보안 수준은 보통 `writing-plans`에서 결정합니다.
- Low: 개인 로컬용. 입력 처리, 경로 처리, 시크릿, 로그, 에러, 권한, 삭제/덮어쓰기 동작을 점검합니다.
- Medium: 외부 API, 민감 저장 데이터, 공유 기기 접근. Low 항목에 더해 저장소와 접근 제어를 검토합니다.
- High: 다중 사용자, 공개 서버, 매우 민감한 데이터. 인증, 인가, 전송 보호, 저장 보호를 분리 설계합니다.
- 보안 설계가 선택한 수준보다 무거워 보이면 이유를 설명하고 확인을 받습니다.

## Git
- 현재 요청의 증거로 파일 이력이나 기존 변경 사항이 필요한 경우에만 읽기 전용 Git 명령을 직접 사용합니다.
- 관련 없는 작업에는 Git 점검을 기본 사전 절차로 수행하지 않습니다.
- stage, commit, push, pull, merge, branch 또는 worktree 변경, discard 또는 cleanup, identity 선택, SSH 계정 점검을 포함한 Git workflow 결정과 상태 변경 Git 작업에는 `git_steward` 커스텀 에이전트를 사용합니다.

## Code Design
- 각 파일, 클래스, 함수는 역할을 하나씩만 갖게 합니다.
- 코드가 무엇을 하는지 드러나는 구체적인 이름을 사용합니다.
- 관련 로직은 붙이고, 관련 없는 로직은 분리합니다.
- 변경 요청이 없는 한 기존 프로젝트 패턴을 따릅니다.
- 더 분명하고 유지보수하기 쉬운 방법이 있으면 하드코딩을 피합니다.
- 하드코딩이 필요했다면 사용자에게 알리고 제거용 리라이트를 제안합니다.
- 라이브러리를 쓰기 전에는 가능하면 Context7로 최신 버전을 확인하고 호환성과 안정성에 맞게 조정합니다.
- 전역 설치보다 Python `venv` 같은 프로젝트 로컬 환경을 우선합니다.
- 같은 요청의 코드 작업이 이미 네 번 이상 실패했다면, 추가 수정 전에 원인부터 디버깅합니다.
